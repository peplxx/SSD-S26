# Standard Protocols

A service provider may delegate (parts of) the IAM process to a 3rd-party identity provider. Popular protocols used for that include:

- [Open Authorization (OAuth)](https://datatracker.ietf.org/doc/html/rfc6749) is a standard framework for enabling a third-party application to obtain limited access to an HTTP service. Obtained access tokens are typically used for social login.

- [OpenID Connect (OIDC)](https://openid.net/developers/how-connect-works/): extends OAuth with capabilities for authentication and user info sharing using an additional ID Token (JWT). Typically implemented in enterprise Single-Sign-On (SSO).

- [Security Assertion Markup Language (SAML)](https://en.wikipedia.org/wiki/SAML): older standard for exchanging authentication and authorization data between an identity provider and a service provider using the XML-based SOAP. Gradually being phased-out in favor of OIDC.

## Task 2: Social login with GitHub

Implement a minimal application for social login with GitHub using OAuth2.0.

1. Create an OAuth app at <https://github.com/settings/developers>. Obtain Client ID and Client Secret.

2. Set Authorization callback URL to an endpoint you expose (e.g., <http://localhost:5000/authorize>).

3. Implement simple frontend and backend in your favourite programming language and framework (we recommend Python+Flask for simplicity).

    - Frontend should present a working "Login with GitHub" button.
    - After successful login, redirect back to the app and show logged-in user details.
