# Fuzz Testing

> <https://en.wikipedia.org/wiki/Fuzzing>

Fuzzing or fuzz testing involves providing invalid, unexpected, or random data as inputs to programs, then monitor for crashes, hangs, or memory-related issues.

## Practice

1. Run AFL++ in docker, then exec into the container's `/tmp` directory.

    ```bash
    docker run --name afl -itd aflplusplus/aflplusplus
    docker exec -it -w /tmp afl bash
    ```

1. Create `buggy.c`. It'll attempt a null pointer dereference when specific input is fed.

    ```c
    #include <stdio.h>
    #include <string.h>

    int main() {
        char buf[100];
        int len = read(0, buf, sizeof(buf) - 1);
        if (len >= 4 && strncmp(buf, "FUZZ", 4) == 0) {
            if (len > 10) {
                char *ptr = NULL;
                *ptr = 1; // Crash!
            }
        }
        return 0;
    }
    ```

1. Compile the program with AFL instrumentation.

    ```bash
    afl-gcc-fast -Wall -Werror -g -std=c99 -O0 ./buggy.c -o buggy
    ```

1. Prepare `input` directory with seed corpus (normal input to be mutated by the fuzzer).

    ```bash
    mkdir inputs
    echo "FUZZtest" > inputs/testcase.txt
    ```

1. Run the fuzzer for a while until a crash is detected. Inspect the results in `output` directory.

    ```bash
    afl-fuzz -i inputs -o output -s 0 ./buggy
    ```
